# 관련성 검수 결과의 정답 파일 변환

## 최신 상태: 2026-10-26, 문서 목록 v2

내보내기의 기본 입력을 검수 화면과 같은 v2 문서 7개 및 v2 응답으로 맞췄다.
`.local-data/acrc-qrels-v2/`를 새로 생성했으며 이전 v1 결과와 응답은 유지했다.
기존 확정 판단 280쌍(관련 96, 무관 184)은 보존된다. 기존 경찰 사례 107건에서
새 문서 4개에 대한 미선택 판단은 428개, 기존 보류는 41개다. 따라서 7개 문서에 대해
완전히 확정된 질의는 아직 0건이다. 나머지 393건은 관련성 검수를 시작하지 않았다.

미선택과 보류를 음성 정답으로 채우지 않는다. 집계에는 각각 `unselectedPairs`,
`unsurePairs`를 기록한다. 이 두 수치는 검수를 시작한 질의에 대한 값이고, 미검수
393건은 `unreviewedQueries`로 별도 기록한다. 문서 수에 따른 Top-K 포화 채널도
계산한다. 현재 유형 기준 1개는 여전히 포화 상태이며 공식 안내는 6개로 확장되었다.
이용 조건, 구조화 DTO, 검색 지식 검수 및 나머지 평가 정답이 준비되지 않아 실제
임베딩/검색 성능 실험은 실행하지 않았다.

기본 입력은 v2이며 `--source`, `--corpus`, `--responses`, `--privacy`로 과거 스냅샷을
명시할 수 있다. 다시 실행할 때는 새 `--output` 경로를 사용한다. Python 테스트
35개가 통과했고, 확장된 문서의 빈 판단이 완료로 계산되지 않는 회귀 테스트를 포함한다.

## 이전 v1 스냅샷

사용자가 검수를 마쳤다고 알려준 뒤 실제 저장 파일을 확인하고, 응답을 변경하지 않은 채
문서 관련성 정답(qrels) 스냅샷을 생성했다. 개인정보 검수 500건 완료와 관련성 검수 완료는
별개다. 실제 관련성 응답은 경찰민원 107건에 존재한다.

| 항목 | 수량 |
|---|---:|
| 관련성 응답 사례 | 107 |
| 모든 문서의 관련/무관 판단 확정 | 85 |
| 보류 포함 사례 | 22 |
| 미응답 사례 | 393 |
| 관련 판단 | 96 |
| 무관 판단 | 184 |
| 보류 판단 | 41 |

확정된 사례의 기존 분리안은 dev 14건/test 71건이고 그룹 중복은 없다.
보류 사례에도 일부 문서는 확정 판단이 있어 쌍 단위 qrels에는 포함한다.
질의 단위 평가 대상으로는 세 문서가 모두 확정된 85건만 별도 기록한다.

## 출력

`.local-data/acrc-qrels-v1/`:

* `qrels.jsonl`: 확정된 280개 질의-문서 쌍. 1=관련, 0=무관.
* `resolved-queries.jsonl`: 세 문서 판단이 확정된 85건과 채널별 관련/무관 문서 ID.
* `pending.jsonl`: 보류 22건의 문서별 이유 및 미응답 393건.
* `summary.json`: 집계, 입력 해시, 미완료 조건.

이 파일들은 아직 Java EvaluationDataset 입력이 아니다. 문서 범위는 현재 후보 3개뿐이다.
없는 정답을 빈 목록이나 false로 채우지 않았으며 근거 상태·위험·사례 없음 정답은 null이다.
기존 검수 응답과 문서 목록은 수정하지 않는다. 같은 출력 폴더를 덮어쓰지 않는다.

## 다음 실험 전에 필요한 작업

현재 유형 기준 1개, 공식 안내 2개뿐이므로 채널별 K=3으로 전부 반환하면 관련 문서의
Recall@3은 순위와 무관하게 높게 나올 수 있다. 이 데이터로 개선 효과를 주장하면 안 된다.
검증 사례와 경찰 분야의 세부 문서를 확보해 후보를 확장한 후, 새 문서에 대한 관련성을
추가 검수해야 한다. 기존 3개 문서 판단은 버전별로 유지한다.

구조화 초안의 관찰 사실·미확인 코드가 아직 완성되지 않았고, 이용 조건 확인과 검색
지식의 검수도 별도다. GMS 키가 있더라도 raw 민원 원문 임베딩으로 이를 우회하지 않는다.
이번 작업에서는 검색·임베딩 호출이나 실제 검색 성능 측정을 실행하지 않았다.

보류 사례는 관련성 화면에서 ‘판단 보류 포함’을 선택해 다시 볼 수 있다. 보류를 해소하기
어려우면 그대로 유지하며 확정된 정답만 별도로 사용한다.

## 검증과 재현

```powershell
.\.local-data\collector-venv\Scripts\python.exe -m unittest discover -s tools/public_complaints -v
.\.local-data\collector-venv\Scripts\python.exe tools/public_complaints/export_relevance.py --output .local-data/acrc-qrels-v2
```

질의·문서 스냅샷 해시, 개별 본문 해시, 개인정보 검수 상태, 문서 ID, 분리 그룹을 검증한다.
미선택/보류가 무관 정답으로 변환되지 않는지, 문서 변경·잘못된 ID를 거부하는지 테스트한다.

변경 파일: `tools/public_complaints/export_relevance.py`, `test_export_relevance.py`, 이 문서.
