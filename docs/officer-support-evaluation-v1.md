# 경찰관 업무 지원을 위한 검색 평가

기준일: 2026-10-29. 사용자 확인에 따라 검색의 업무상 수혜자를 **민원을 처리·안내하는
경찰관**으로 명시했다. 민원인의 발화는 검색 입력이며, 그 사람이 직접 신청 방법을 묻는지와
검색 근거가 경찰관의 업무에 유용한지는 별개의 문제다.

2026-10-30 후속 작업은 [묶음 평가와 자료 수집 후보](officer-support-followup-v2.md)에
별도로 기록한다. 이 문서의 v1 결과는 당시의 미완료 상태 그대로 보존한다.

## 이번 수정

기존 실험은 공식 안내를 직접 근거로 인정하려면 민원인이 현재 절차 질문을 해야 한다고
정의했다. 이 조건은 폐기한다. 예를 들어 “지갑을 잃어버렸으니 찾아 달라”는 발화에서도
경찰관에게는 분실 신고·조회 절차가 안내 근거가 될 수 있다.

반대로 경찰이나 민원이라는 단어가 등장한다는 이유로 모든 절차 문서를 관련 있다고
판정하지 않는다. 현재 상황과 해당 문서의 구체적인 적용 범위를 연결해야 한다.
경찰민원24 신청 결과 확인과 형사사건 수사 진행 조회, 사고 사실확인원 발급과 과실 판단,
실종 예방 사전등록과 현재 실종 상황을 각각 구분한다. 이 구분은 실험 후보 문서의 범위에
대한 것으로, 실제 사건의 처리 경로나 법적 결론을 확정하는 것이 아니다.

## 채널별 평가 기준

| 채널 | 경찰관에게 유용한 근거 | 인정하지 않는 추론 |
|---|---|---|
| VERIFIED_CASE / Top 5 | 핵심 사실과 맥락이 유사한 검증 사례 | 키워드만 같은 사례, 사례 없는 강제 추론 |
| CATEGORY_REFERENCE / Top 3 | 관찰 사실에 따라 상황·업무 유형을 구분하는 기준 | 최종 범죄 성립·유무죄 판단 |
| OFFICIAL_GUIDE / Top 3 | 해당 상황에서 안내할 절차·확인 정보·문서 범위를 설명하는 자료 | 민원인의 명시적 절차 질문을 필수로 요구, 처리 결과 보장 |

등급 2는 구체적 업무에 직접 유용, 1은 관련 배경, 0은 무관하거나 다른 절차,
UNASSESSABLE은 정보 부족이다. 등급 2에는 지원하는 경찰관 업무와 입력 출처 ID를
반드시 기록한다. 출처 ID의 존재만으로 의미적 정확성을 인증하지는 않는다.
판단 불가를 음성으로 바꾸지 않으며, 등급 1을 운영 검색에서 일괄 제거하지 않는다.
위험 신호 보존 및 근거 부족·모호성 처리는 기존 모듈의 책임으로 유지한다.

## 기존 데이터의 포함 범위 확인

[집계 파일](results/officer-coverage-v1.json)은 출처 메타데이터와 기존 AI 구조화 코드를
집계한 것이다. 새로운 정답 판정이나 원문 전체의 재검수 결과가 아니다.

- 전체 500건 중 출처가 경찰민원인 사례는 107건(21.4%)이다.
- 개발용 100건 중 경찰민원은 17건이다. 주택건축민원은 28건이다.
- 기존 AI 코드 기준 전체 500건에 LOST_ITEM 0건, PATROL_REQUEST 0건,
  CYBER_TRANSACTION 2건이다. 0은 원문에 해당 내용이 전혀 없다는 증명이 아니다.
- 경찰민원 개발 17건의 코드는 경찰 서비스 민원 9, 교통 행정 5, 처리 현황 2,
  안전 위협 1이다. 출처가 경찰민원인 것과 실제 현장 업무를 대표하는 것은 다르다.
- 후보 20개는 유형 기준 4개와 공식 안내 16개다. VERIFIED_CASE 후보는 0개이므로
  유사 사례 검색의 품질은 이 자료로 검증할 수 없다.

## 개발 실험 설계

기존 dev/test 분할을 유지하고 경찰민원 출처의 개발 17건에만 새 평가를 실행한다.
각 사례에 후보 20개를 보여주고 두 모델이 독립 판단한다. 실제 사례는 680개 문서 라벨,
34개 응답이다. 여기에 직접 작성한 대조 사례 12건을 각 1개 문서와 짝지어 24개 응답을
수집한다. 전체 58개 응답이며 합성 사례를 실제 수집 건수에 추가하지 않는다.

모델에는 기존 라벨·검색 순위·AI 구조화 코드·대조 사례 기대 등급을 전달하지 않는다.
원문은 기존 개인정보 점검의 해시를 확인한 maskedText만 사용한다. 개별 응답과 판단
이유는 Git 제외 로컬 경로에 저장하고 공개 결과에는 집계만 포함한다.

후보는 기존 v3에서 별도 복사했다. 고충민원 신청 안내의 평가자 작성 boundary에 있던
명시적 절차 질문 조건만 수정했다. 공식 문서 본문은 변경하지 않았고 새로 원문을
확인했다는 의미도 아니다. 모든 후보는 실험용 DRAFT 상태이며 운영 DB에 승격하지 않는다.

프롬프트·후보·입력·대조 사례·모델을 해시로 고정한다. 기존 벤치마크 v3는 그대로
보존하며 기존 Recall과 새 관련성 등급을 같은 지표처럼 비교하지 않는다.

## 파일럿 실행 결과와 미해결 사항

[집계 파일](results/officer-rubric-dev-v1.json)에 `complete: false`로 기록했다.
58개 예상 응답 중 55개만 형식·출처 검증을 통과했다. mini의 실제 개발 사례 응답 3개는
재시도 후에도 2개에서 문서 라벨 수가 맞지 않고 1개에서 출처 ID가 부적절했다.
이 3건의 응답은 채택하지 않았고 누락 라벨을 무관으로 채우지 않았다.
따라서 **전체 파일럿 평가 완료나 운영 품질 검증으로 보고하지 않는다.**

비교 가능한 실제 개발 사례는 14건이다. 공식 안내 224개 문서 쌍에서 직접 근거 여부의
모델 간 일치율은 98.66%, 양성 일치율은 90.91%, 등급 자체의 일치율은 91.07%였다.
유형 기준 56개 쌍은 모두 직접 근거 양성이 없어 100% 일치해도 판별력을 입증하지 못한다.
높은 일치율은 정확도나 Recall 향상을 의미하지 않는다. 제외된 3건에 따른 선택 편향도 있다.

합성 대조 12건은 두 모델 모두 응답했다. 작성한 기대 등급과의 일치는 mini 9/12,
4o 12/12였다. mini는 과거 분실을 언급한 경찰 서비스 민원과 형사사건 진행 문의를
각각 분실 신고·경찰민원24 안내의 배경 근거로 보았고, 온라인 거래와 무관한 임대차
보증금 문제에는 사이버 신고 안내를 직접 근거로 인정했다. 특히 마지막 경우는
문서 적용 범위를 넓게 추정한 오류로, 업무 관점을 명시하는 것만으로 해결되지 않았다.
4o의 합성 일치를 실제 민원 정답률로 쓰거나 4o를 정답 제공자로 확정하지 않는다.

결정: 경찰관 목적은 확정하되 새 AI 라벨은 실험 상태로 남긴다. 후속 실행에서는
실패 응답을 줄이기 위한 작은 문서 묶음 또는 출력 스키마 검증을 별도 버전으로 시험하고,
범위가 다른 민원을 같은 업무로 추정하는 대조 사례를 유지한다. 이번 라벨로 운영
임계값을 조정하거나 기존 500건 정답을 교체하지 않는다.

## 다음 데이터 구성 원칙

새 평가 자료의 수집 기준은 민원인의 질문 표현이 아니라 경찰관의 업무 범위다.
유실물, 교통 행정, 온라인 거래 피해, 순찰 요청, 사건 진행 문의, 경찰 서비스 민원,
안전 위협, 일반 상담을 포함하고 각 업무에서 직접 유용한 근거·무관한 근거·근거 부족을
함께 구성한다. 안전 위협은 최종 긴급 경로 판단이 아닌 위험 신호 보존을 확인한다.

공개된 실제 사례와 공식 문서만 활용하고 출처·비식별 점검·AI 라벨 출처를 기록한다.
공개 민원 처리 사례가 현장 접수 분포를 대표한다고 가정하지 않는다. 확보하지 못한 업무는
미검증으로 남기고 합성 자료는 별도 집계한다. 서로 유사한 원문·파생 사례는 같은 그룹으로
묶고 개발/최종 평가를 나눈다. 학습·튜닝에 이미 사용한 자료를 새 독립 평가 자료로 부르지 않는다.

목적에 맞는 자료와 라벨을 고정한 뒤 동일한 후보·벡터에서 기본 검색과 기존 개선 전략의
채널별 Recall@K, Precision@K, MRR, 사례 없음 거부, 모호성 감지, 위험 신호 보존을 비교한다.
검증 사례 후보가 없으면 해당 채널 성능은 미측정으로 표시한다.

## 변경 파일과 범위

- README, 이전 채널 기준 보고서: 경찰관 목적과 이전 기준의 한계 명시.
- 이 문서: 새 기준·데이터 포함 범위·실험·다음 검증 정의.
- `tools/public_complaints/officer_documents_v1.json`: 분리된 평가 후보.
- `tools/public_complaints/officer_rubric_pilot.py`, `test_officer_rubric_pilot.py`: 새 기준의 AI 평가와 검증.
- `tools/public_complaints/audit_officer_coverage.py`, `test_audit_officer_coverage.py`: 기존 자료의 포함 범위 집계와 입력 연결 검사.
- `docs/results/officer-coverage-v1.json`, `docs/results/officer-rubric-dev-v1.json`: 개별 민원 없는 집계.

변경하지 않는다. Java 운영 코드 변경이 없어 이번 단계에서는 Java 테스트를 재실행하지 않는다.
