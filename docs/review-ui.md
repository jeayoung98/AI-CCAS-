# 한 건씩 민원 검수하기

화면: http://127.0.0.1:8765

1. 왼쪽 민원 내용과 ‘요약 초안과 코드 후보’를 읽는다.
2. 오른쪽 6개 질문에 통과 / 수정 필요 / 판단 보류를 선택한다.
3. 수정할 내용이나 보류 이유를 메모한다. 개인정보 원문은 다시 적지 않는다.
4. ‘저장하고 다음’을 누른다. 선택·메모는 0.7초 뒤 자동 저장도 된다.
5. ‘저장 완료’가 표시됐는지 확인한다. 저장 실패 시 다음 사례로 이동하지 않는다.

기본은 경찰민원 107건이다. ‘전체 민원’으로 바꾸면 500건을 볼 수 있다.
‘아직 답하지 않은 건’은 6개 항목이 모두 채워지지 않은 사례를 보여준다.
보류를 선택해도 응답 완료로 집계되며, 이를 데이터 승인으로 취급하지 않는다.
이용 조건 확인과 검색 문서 관련성 정답은 이 화면의 6개 응답과 별도 작업이다.

응답 파일: `.local-data/acrc-human-review/responses.json`

검수자가 선택한 상태, 메모, 별칭, 사례 ID, 본문 해시, 수정 시각, 수정 번호를 저장한다.
이 파일은 Git에서 제외되며, 원본 500건·초안·maskingCompleted 값을 변경하지 않는다.
브라우저 저장소가 아닌 파일 저장이므로 브라우저를 새로 열어도 이어서 검수할 수 있다.
여러 창에서 같은 사례를 수정하면 오래된 응답이 새 응답을 덮어쓰지 않도록 충돌을 알린다.

서버가 꺼졌거나 PC를 다시 켰으면 프로젝트 PowerShell에서 실행한다.

```powershell
.\tools\Start-Review.ps1
```

명령은 서버를 숨김 창으로 실행한다. 위 화면 주소를 열면 된다. GMS 키는 필요 없다.
서버는 127.0.0.1에만 바인딩하며 외부 API나 CDN에 자료를 보내지 않는다.
저장은 임시 파일을 기록한 뒤 교체하며, 다른 데이터 버전에 기존 응답을 붙이지 않는다.

검수 후 채팅에서 “저장한 응답 확인해줘”라고 하면 해당 파일을 읽어 변경할 내용을
정리할 수 있다. 서버를 켜두었다고 제가 자동으로 응답을 감시하는 것은 아니다.

검증: Python 테스트 25개 통과(저장·재시작 복원·부분 응답·입력 검증·다른 출처 요청 거부·
수정 충돌·데이터 변경 거부 포함). 실제 응답 파일에 테스트용 판단을 넣지 않았다.

변경 파일: `tools/public_complaints/review_server.py`, `review.html`, `test_review_server.py`,
`tools/Start-Review.ps1`, `docs/review-ui.md`.
