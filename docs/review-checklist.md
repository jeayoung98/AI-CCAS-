# 지금 판단해 주실 내용

2026-10-26 현재: 사용자가 500건의 개인정보·내용 등 6개 검수 항목을 통과로 확인했고,
응답은 `.local-data/acrc-human-review/responses.json`에 저장되어 있다. 아래는 해당
검수에 사용한 기준이다. 이용 조건 확인, 구조화 DTO 완성, 검색 정답 검수는 별도다.
현재 필요한 문서 관련성 판단은 [최신 내보내기 상태](relevance-export.md)를 따른다.
화면은 `http://127.0.0.1:8765/relevance`이며 새 문서 428개 판단과 기존 보류 41개가 남아 있다.

500건의 자동 추출 초안을 검수할 때는 우선 경찰민원 107건부터 보고, 각 항목에
**통과 / 수정 필요 / 판단 보류** 중 하나와 짧은 이유를 남기면 된다.
한 사람이 모든 분야를 판단할 필요는 없다. 모르는 내용은 보류로 남긴다.

## 1. 개인정보: 이 내용을 검색 서비스에 사용해도 되는가?

확인할 것: 개인 이름, 전화번호, 이메일, 주민번호, 차량번호, 상세주소,
사건번호와 여러 정보를 조합하면 특정 사람을 알아볼 수 있는 내용.

* 통과: 필요한 가림이 완료되어 개인을 식별할 정보가 남지 않음.
* 수정 필요: 남은 개인정보를 추가로 가려야 함. 원래 개인정보를 메모에 다시 적지 않는다.
* 보류: 개인정보인지 또는 재식별 가능한지 판단하기 어려움.

204건에 추가 가림이 적용됐지만 이것이 개인정보 검수 통과를 뜻하지 않는다.
기존 주소 가림이 있는 67건은 중요한 사건 내용까지 지워지지 않았는지도 확인한다.

## 2. 내용: 초안이 실제 민원 내용을 정확히 담고 있는가?

| 확인 질문 | 판단 기준 |
|---|---|
| 누가 무엇을 했다는 내용인가? | 신청인의 주장과 확인된 사실을 섞지 않았는지 |
| 무엇을 요청하는가? | 현재 요청과 과거에 신고·신청했던 이력을 구분했는지 |
| 위험 표현이 있는가? | 흉기·협박·학대 등의 표현이 실제 서술인지, 부정·인용인지 |
| 지금 진행 중인가? | 오래된 사건을 현재 위험으로 바꾸지 않았는지 |
| 코드 후보가 맞는가? | 민원 대상과 요청 행위가 문장 근거와 맞는지 |
| 판단할 내용이 충분한가? | 잘린 발췌 41건은 뒷부분 확인 전 확정하지 않기 |

예: “예전에 신고했지만 경찰의 대응이 부당해 조사해 달라”는 과거 신고 이력이 있는
업무처리 불만이다. 단지 ‘신고’가 들어 있다는 이유로 현재 요청을 REPORT로 확정하지 않는다.
위험 코드 후보가 없더라도 ‘위험 없음’이 검증된 것은 아니다.

최종 범죄 성립 여부, 최종 민원 분류, 112/182 등 최종 처리 경로는 판단하지 않는다.
그 판단은 이 검색 모듈의 검수 범위가 아니다.

## 3. 같은 사건인가?

유사 후보 4쌍은 같은 사건의 재게시인지, 주제만 비슷한 별개의 사건인지 확인한다.
가림 처리로 구별이 어려우면 보류한다. 같은 사건은 개발용과 평가용 양쪽에 나누지 않는다.
현재 dev 100건/test 400건은 확정 전 초안이다.

## 4. 자료를 이 목적으로 사용해도 되는가?

원 출처의 이용 조건을 확인한다. 현재 자료에는 공공누리 3유형 및 AI 이용 안내가 기록돼 있다.
공개 페이지라는 이유만으로 가공·배포·상업적 사용까지 모두 허용된다고 가정하지 않는다.
팀의 실제 이용 목적에 대해 판단이 어려우면 담당자 또는 권리자 확인 전 보류한다.

## 5. 검색 정답: 이 문서가 질문에 관련된 근거인가? (검색 지식 확보 후)

검수 화면의 문서 후보를 다음 기준으로 판단한다. 후보의 관련성 판단과 검색 지식의
DB 적재 승인은 별개다.

| 채널 | 판단할 내용 |
|---|---|
| 검증 사례 | 사실·대상·요청 목적이 유사하고 참고할 수 있는 사례인가? |
| 유형 기준 | 해당 상황을 설명하거나 구별하는 기준인가? |
| 공식 안내 | 실제 질문에 필요한 안내가 포함됐는가? |

각 문서에 **관련 / 무관 / 판단 보류**와 근거 문장을 기록한다.
다른 분야의 민원이라고 자동으로 ‘관련 문서 없음’으로 정하지 않는다.
사례가 없어도 공식 안내는 관련될 수 있고, 같은 단어가 있어도 질문과 무관할 수 있다.
정답을 모르겠으면 null(미검수)을 유지한다. 빈 목록 []은 검토 후 관련 문서가 없다는 뜻이다.

## 기록 예시

```text
사례 ID: acrc-xxxxx
개인정보: 수정 필요 — 상세 위치 추가 가림 필요
내용·코드: 수정 필요 — 과거 신고 이력을 현재 요청으로 잘못 잡음
현재성: 판단 보류 — 발췌에서 확인 불가
동일 사건 여부: 판단 보류
이용 조건: 판단 보류
검토자 / 검토일: 실제 검토한 사람과 날짜
```

초안 파일: `.local-data/acrc-drafts-500-v2/drafts.jsonl`
검수 응답 파일: `.local-data/acrc-human-review/responses.json`
문서 관련성 응답 파일: `.local-data/acrc-human-review/relevance-responses-v2.json`
검수 화면에서 저장하면 상태·검토자·검토일·이유가 기록된다.
‘통과’는 본인이 확인한 항목에만 표시한다.

## GMS 실행 설정

키는 현재 Windows 사용자로 암호화해 `.local-data/gms/api-key.dpapi`에 저장한다.
키 파일은 Git 제외 대상이고, 다른 사용자/컴퓨터에서 그대로 복호화할 수 없다.
다음 명령을 실행한 PowerShell 창에서 Gradle을 실행한다.

```powershell
. .\tools\Use-Gms.ps1
```

기존 임베딩 클라이언트가 사용하는 OPENAI_API_KEY와 OPENAI_BASE_URL을 현재 세션에만
설정한다. 모델/차원은 기존 text-embedding-3-large / 1536을 유지한다.
키는 문서·소스에 넣지 않으며, 500건을 키 설정만으로 전송하지 않는다.
