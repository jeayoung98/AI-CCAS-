# 채널별 관련성 기준의 개발 데이터 실험

> 목적 정정: 이 문서는 과거 탐색 실험 기록이다. 신청 안내에 민원인의 명시적 절차 질문을
> 요구한 기준은 경찰관 업무 지원 목적에 맞지 않아 채택하지 않는다. 현재 기준과 다음 작업은
> [경찰관 업무 지원 평가](officer-support-evaluation-v1.md)를 따른다. 아래 결과와 입력 해시는
> 재현을 위해 보존하며 경찰관 업무 지원 품질의 증거로 사용하지 않는다.

기준일: 2026-10-29. 기존 이진 관련성 판단의 불일치가 집중된 두 문서를 대상으로
채널별 평가 기준을 시험한다. 기존 `public-500-pool20-ai-v3` 벤치마크와 운영 설정은 보존한다.
새 기준이 더 정확하다고 가정하지 않으며 이번 단계에서는 평가 400건을 모델에 전달하지 않는다.

## 기준

| 등급 | 의미 |
|---|---|
| 0 | 현재 요청과 무관 |
| 1 | 주제와 관련된 배경 설명이지만 해당 채널의 직접 근거는 아님 |
| 2 | 해당 채널의 목적에 맞는 직접 근거 |
| UNASSESSABLE | 발췌·현재 요청 정보 부족으로 판단하기 어려움 |

유형 기준 문서는 현재 민원이 행정기관의 부당한 처분·소극 대응·불합리한 제도를
문제 삼는 상황인지 설명하는 데 도움이 되면 2점을 줄 수 있다. 신청 방법을 직접 묻지
않아도 해당한다. 다만 그 기관이 실제로 위법했다는 법적 판단으로 확장하지 않는다.

공식 신청 안내 문서는 현재 요청이 신청 방법, 제출 창구, 준비 자료, 신청 상담일 때
2점을 준다. 처분 취소·보상·조사·문제 시정 자체를 요구하는 글에 일반 신청 방법을
제시하는 것은 이 실험에서는 배경 설명인 1점으로 구분한다. 과거에 신청하거나 신고한
사실만으로 현재도 신청 절차를 묻는다고 추정하지 않는다.

이는 **직접 도움과 배경 설명을 구분하기 위한 실험 정의**다. 배경 안내도 후단 AI에
유용할 수 있으므로 1점을 운영 검색에서 삭제하거나 모든 목적에서 무관하다고 취급하지 않는다.
기존 RELEVANT 라벨과 등급 2는 정의가 다르며 서로의 Recall을 직접 비교하지 않는다.

## 실험 설계

- 기존 개발 데이터 100건만 사용한다. 기존 dev/test 그룹 중복이 없는지 확인한다.
- 대상은 `acrc-grievance-definition-v1`, `acrc-grievance-application-v1` 두 문서다.
- 두 기준 모두 동일한 전체 20개 후보를 문맥으로 보여주고 위 두 문서만 판단하게 한다.
- `gpt-4o-mini`, `gpt-4o` 각각 기존 이진 기준과 새 등급 기준으로 평가한다.
- 100건 × 2문서 × 2모델 × 2기준 = 800개 라벨, 모델 호출은 400개다.
- 질의마다 모델과 기준을 번갈아 실행하고 동일한 온도 0을 사용한다.
- 이전 판단·검색 점수·질의 구조화 코드는 모델에 보여주지 않는다.
- 실행 전에 입력·두 프롬프트의 해시, 대상 문서, 모델, 선택 질의 목록을 저장한다.
- 완료된 응답은 체크포인트로 재사용하며 프롬프트가 바뀌면 같은 실행을 재개하지 않는다.

## 지표와 해석

등급 2만 직접 근거 양성으로 투영한다. 어느 모델이든 UNASSESSABLE이면 해당 쌍은
새 이진 비교에서 제외하고, 이전 기준도 동일한 질의 집합으로 비교한 지표를 함께 기록한다.
전체 이전 기준의 지표, 제외 수, 등급별 개수도 보존한다.

단순 일치율뿐 아니라 우연 일치를 보정하는 Cohen kappa, 양성 일치율
`2 × 양쪽 양성 / (모델별 양성 수의 합)`, 등급 자체의 일치율을 계산한다.
모두 무관으로 판단하면 일치율은 높지만 양성 일치율과 kappa는 정의되지 않을 수 있다.
이 경우 null로 기록하며 성능 향상으로 간주하지 않는다.

다른 기준의 합의도가 높아져도 정확도가 높아졌다는 증거는 아니다. 라벨의 양성 비율이
달라진 효과와 같은 제공자 모델의 공통 오류도 고려해야 한다. 선정한 두 문서에 대한
개발 실험이므로 전체 후보나 새로운 독립 질의에서의 일반화를 입증하지 않는다.

## 첫 실험 결과: 등급 직접 판단은 채택하지 않음

400개 호출을 완료했으며 판단 불가 쌍은 없었다.

| 대상 | 기존 이진 모델 간 일치율 | 새 직접 근거 일치율 | 새 양성 수 mini / 4o |
|---|---:|---:|---:|
| 유형 기준 | 69% | 100% | 100 / 100 |
| 신청 안내 | 74% | 44% | 56 / 0 |

유형 기준의 100%는 두 모델 모두 모든 사례를 양성으로 본 결과다. 구별 능력의 증거가
아니며 kappa도 정의되지 않는다. 신청 안내는 양성 일치율이 27.78%에서 0%로 떨어졌고,
등급 자체의 일치율은 3%였다. 이 기준으로 기존 정답을 교체하지 않는다.

## 후속 실험: 사실 추출 후 코드로 등급 계산

원문만 보여주고 `administrativeGrievance`와 `asksProcedureNow`를 추출한다.
모델은 문서 등급을 직접 정하지 않는다. 행정기관에 대한 문제 제기가 있으면 유형 기준은
2점, 현재 신청 절차 문의도 있으면 신청 안내 2점, 절차 문의가 없으면 안내 1점이다.
행정기관에 대한 문제 제기가 없으면 두 문서 모두 0점이며 정보 부족은 판단 불가로 남긴다.
이 규칙은 선정한 두 문서만을 위한 실험이며 일반 검색 판정기로 사용하지 않는다.

개발 100건에 직접 작성한 대조 사례 24건(절차 문의 8, 시정 요구 8, 무관 8)을 추가한다.
두 모델로 총 248개 응답을 수집한다. 대조 사례는 실제 민원 500건에 포함시키지 않으며,
작성자가 정한 기대 등급과의 일치는 실제 서비스 정확도가 아니다.
절차 문의가 있다는 판단은 원문에 실제로 존재하는 인용문과 출처 ID가 있어야 한다.
인용문 존재 여부 검사는 의미 해석의 정확성을 보장하지 않는다.

초기 fact v1 실행은 16개 저장, 232개 형식 검증 실패로 미완료됐다. 사실이 없다는 판단에도
출처 ID를 강제한 것이 원인이었다. v2는 false/null의 빈 출처를 허용하고 true에는 출처를
필수로 유지한다. 프롬프트와 버전을 변경하고 별도 디렉터리에서 전량 재실행했다.
v1 부분 응답을 v2에 섞지 않는다.

### 사실 추출 v2 결과

248개 응답 모두 저장했고 최종 실패는 0개다. 실제 사용 모델은
`gpt-4o-mini-2024-07-18`, `gpt-4o-2024-08-06`이다.

| 실제 개발 100건 | 직접 근거 이진 일치율 | 양성 수 mini / 4o | 판단 불가로 제외된 쌍 | 등급 일치율 |
|---|---:|---:|---:|---:|
| 유형 기준 | 96/100 = 96% | 100 / 96 | 0 | 96% |
| 신청 안내 | 92/92 = 100% | 0 / 0 | 8 | 88/92 = 95.65% |

유형 기준은 mini가 전부 양성으로 판단해 kappa가 0이다. 신청 안내는 직접 근거 양성이
한 건도 없어 양성 일치율과 kappa가 정의되지 않는다. 따라서 100%라는 일치율로
실제 절차 문의를 잘 찾는다고 주장할 수 없다. mini의 판단 불가 8건도 음성으로 치환하지 않았다.

| 합성 대조 24건 | 기대 등급 일치 mini | 기대 등급 일치 4o | 판단 불가 쌍 | 두 모델 등급 일치 |
|---|---:|---:|---:|---:|
| 유형 기준 | 22/24 | 24/24 | 1 | 22/23 = 95.65% |
| 신청 안내 | 21/24 | 24/24 | 3 | 21/21 = 100% |

기대 등급 일치의 분모 24에는 판단 불가를 포함한다. 두 모델 간 일치율만 판단 불가 쌍을
제외한다. 명시적 절차 문의 8건은 두 모델 모두 직접 근거로 보았다. 그러나 이는 작성한
대조 사례에서 규칙이 작동한 결과이며, 실제 민원에서의 재현율 검증은 아니다.

### 당시 결정과 다음 검증 제안 (현재는 위 목적 정정으로 대체)

사실 추출 방식은 직접 등급 판단보다 원인을 추적하기 쉽지만 운영 도입이나 정답 교체를
결정할 근거는 부족하다. 고정 벤치마크 v3와 기존 Recall 수치를 유지한다.
다음 단계는 **실제 현재 절차 문의가 있는 별도 검증 자료 확보**다. 현재 100건은 처분에
대한 이의·시정 요구 중심이므로 긍정 사례 검증에 한계가 있다. 새 자료에는 절차 문의와
단순 시정 요구를 함께 포함하고, 수집 기준·분할·AI 라벨 출처를 별도로 고정해야 한다.
그 후 같은 자료와 기준으로 검색 전략을 비교한다. 기존 test 400건을 새 기준 튜닝에
재사용하거나 합성 사례를 실제 수집 건수에 더하지 않는다.

## 검증과 적용 범위

- Python 평가 도구 테스트 72개 통과.
- 두 완료 실험을 API 키 없이 체크포인트로 재집계하여 결과 파일이 바이트 단위로 동일함을 확인했다.
- `git diff --check` 통과.
- 고정 벤치마크 해시 검사 통과. 평가용 400건의 라벨을 변경하거나 이번 모델 호출에 사용하지 않았다.
- Java 운영 코드 및 검색 설정 변경 없음. 이번 단계에서는 Java 테스트를 재실행하지 않았다.
- 개별 민원과 모델 판단 이유는 Git 제외 디렉터리에 보관하고, 공개 변경에는 집계만 포함한다.
- 두 모델은 같은 제공자이므로 공통 오류가 가능하다. 이번 결과를 Recall 향상이나 최종 분류 정확도로 표현하지 않는다.
